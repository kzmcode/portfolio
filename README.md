# Portfolio — From insight to reality

**[kzmcode.dev](https://kzmcode.dev)**

kzm の作品をまとめたポートフォリオサイトのソースコードです。個人開発や仕事で作ってきた Web アプリ・モバイルアプリ・デスクトップアプリを、プレビュー動画つきで紹介しています。

## サイトの内容

- **Hero**：パーティクルで描くオブジェクトのアニメーション
- **About**：自己紹介
- **Works**：作品の一覧。カードを開くと、デバイスフレームの中でプレビュー動画が再生され、説明・使用技術・公開 URL・GitHub へのリンクが表示される
- **Contact**：問い合わせフォーム

## 技術スタック

| 分類 | 使用技術 |
|---|---|
| フレームワーク | Astro 7 |
| 言語 | TypeScript |
| ホスティング | Cloudflare Workers + Static Assets |
| コンテンツ | Astro Content Collections（作品ごとの YAML） |
| データベース | Cloudflare D1 + Drizzle ORM（問い合わせのみ） |
| バリデーション | Zod |
| スパム対策 | Cloudflare Turnstile |
| メール通知 | Cloudflare Email Routing |

## 設計のポイント

### ページは静的生成、Worker の処理は最小限

作品データは Astro のコンテンツコレクションで、1 作品 1 フォルダ（`src/content/works/<slug>/` に `work.yaml`・プレビュー動画・ポスター）としてリポジトリで管理しています。トップページはビルド時にこれを読み込んで静的な HTML として出力するため、リポジトリさえあればどこからでもビルド・デプロイできます。リクエストのたびに Worker で動くのは、問い合わせの API と動画の配信だけです。

### 管理画面は本番に置かない

作品の追加・編集に使う管理画面は、ローカルの開発サーバーでだけ有効になります。Astro のインテグレーションで `astro dev` のときだけルートを追加しているため、本番のビルドには含まれず、外部から攻撃される入口になりません。保存は dev サーバーの Node 側で `work.yaml` や動画ファイルを書き換える形なので、変更はそのまま Git の差分になります。

### 動画もリポジトリで管理

作品のプレビュー動画とポスター画像はリポジトリに置き、静的アセットとして配信しています。静的アセットの配信は Range リクエストに 206 で応答しないため、そのままでは Safari で動画が再生されません。そこで動画だけは専用のルートを経由させ、要求された範囲を切り出して返しています。

### 問い合わせフォーム

Turnstile（Invisible）で検証したうえで内容を D1 に保存し、Email Routing でメール通知しています。IP アドレスのハッシュを使って、短時間に送信が集中した場合は受け付けないようにしています。

### セキュリティ

Astro が出力するインラインのスクリプト・スタイルにはハッシュつきの CSP を `<meta>` で適用し、`<meta>` では指定できない `frame-ancestors` などはレスポンスヘッダーで付与しています。

## ディレクトリ構成

```
src/
  pages/          トップ・プライバシーポリシー・404・サイトマップ・問い合わせ API・動画配信
  components/     ページを構成する各セクション
  scripts/        パーティクル・スクロール連動・モーダル・フォーム送信（ブラウザ側）
  lib/            バリデーション・作品データ・メール・Turnstile など
  db/             Drizzle のスキーマ
  admin/          ローカル専用の管理画面
  content/        サイトの文言・リンク、作品（works/<slug>/ に work.yaml・動画・ポスター）
integrations/     開発時だけ管理画面と保存処理を追加する Astro インテグレーション
migrations/       D1（問い合わせ）のマイグレーション
```
